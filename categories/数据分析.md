## 20. A/B 测试统计解读

**Prompt：**
```
Help me interpret A/B test results.

Test description: [测试描述]
Metric: [核心指标]
Control group: [对照组样本量 + 转化率/均值]
Variant group: [实验组样本量 + 转化率/均值]
Statistical significance threshold: [α值 — 如0.05]
MDE (Minimum Detectable Effect): [最小可检测效应量]
Duration: [测试持续时间]
Early stopping: [是否提前停止]

Provide:

1. Significance test — is the result statistically significant? (p-value)
2. Effect size — how big is the difference practically?
3. Confidence interval — range of the true effect
4. Bayesian interpretation — probability that variant is better (if applicable)
5. Practical significance — is the effect large enough to matter for business?
6. Common pitfalls check — multiple testing, peeking, sample ratio mismatch
7. Segmentation analysis — does the effect vary by segment?
8. Recommendation — launch, iterate, or run a follow-up test?

If the result is not significant: calculate required sample size for a conclusive test.
```
> 📅 2026-07-12
> 来源：A/B Testing / AI Data Science (2026)
> 用法：A/B测试结果解读——不只p值，还看效应量、置信区间、实用显著性和常见陷阱。

## 107. 异动归因分析框架

> 📅 2026-09-02

**Prompt：**
```
Act as a senior analytics lead. Metric [e.g. weekly active users / conversion / revenue] changed by [X]% [up/down] between [period A] and [period B]. Available data: [describe tables/dimensions you can slice by]. Walk me through a rigorous attribution:
1. Verify the change first: is it real (data quality, definition change, seasonality, holiday, platform bug) or a true metric shift?
2. Dimension drill-down: which segments (channel, cohort, region, device, plan) drove the change? Ask me for the slices or propose the exact SQL/query for each
3. Decompose the delta: how much is new-vs-returning, volume-vs-rate, price-vs-mix (as applicable)
4. Correlate with events: product releases, campaigns, outages, competitor moves in the window
5. Deliver a one-page summary: confirmed cause(s), confidence level per cause, and the 2 metrics to watch next week
Never present correlation as causation — label it.
```
> 来源：Google Cloud BigQuery Gemini / Promptessor — data analysis & anomaly attribution prompts
> 用法：指标异动先证伪再归因：数据质量/季节/口径检查 → 维度下钻找驱动段 → 增量分解 → 事件关联，逐条标注置信度，绝不把相关当因果。
