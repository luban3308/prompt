## 1. 操作系统手册式系统提示词

**Prompt：**
```
Write a system prompt for an AI agent that reads like an operating manual, not a personality sketch.

Agent role: [角色]
Primary task: [核心任务]
Available tools: [工具列表]
Failure behavior: [明确当任务无法完成时的行为：放弃/上报/降级]

Structure:
1. Identity and mission (2-3 sentences)
2. Operating procedures (numbered steps)
3. Failure behavior (explicit: what to do when stuck, when to ask for help)
4. Output contract (exact format, length, audience)
5. Guardrails (what to never do)

Separate instructions from data using delimiters (XML tags, ---, or """). Include 2-5 examples.
```
> 来源：Musketeers Tech — Prompt Engineering Best Practices for AI Agents (2026)
> 用法：把系统提示词当作"操作手册"而非"人设描写"来写，显式定义失败行为，Agent 在遇到边界情况时不会乱猜或静默出错。

## 2. 意图+上下文+约束三段式（Gemini 结构）

**Prompt：**
```
Intent: [一句话说明你要什么，如：把这份40页路线图总结成5条要点]
Context: [背景，如：我要向不懂技术的董事会汇报]
Constraints: [约束，如：不要用术语、不超过120词、只讲商业影响和时间线]

[粘贴材料]
```
> 来源：Phrasly — Best Prompts for Gemini AI (2026 Guide)
> 用法：Gemini 对 Intent + Context + Constraints 三段式结构响应最佳，比 ChatGPT 式角色扮演提示更有效；同一任务用不同结构输出质量差异巨大。

## 3. 目标-成功标准-限制条件定义法（推理模型专用）

**Prompt：**
```
解决以下问题：[问题背景]

成功标准：
1. [可验证的输出标准]
2. [必须满足的限制条件]

规则：
- 不要一步步向我展示推理过程
- 由你自行选择最高效的解法路径
- 完成后用两句话说明你的判断依据
```
> 来源：Data-DI Blog — 2026 提示词技巧全面升级（OpenAI 官方 2026 指南解读）
> 用法：推理模型（GPT-5.x 等）的最佳实践是只定义目标结果、成功标准与限制条件，让它自己选路径；旧式"先做A再查B"的步骤指令反而会拖累推理模型表现。

## 5. 输出契约固定法

**Prompt：**
```
Pin the output contract for this agent:

Output format: [JSON schema / Markdown 表格 / 固定段落结构]
Length: [明确字数或行数]
Audience: [读者/调用方]
Tone: [语气]

Rules:
- 无论输入如何变化，输出结构保持不变
- 缺失信息用 null 或 "N/A" 显式标注，不要编造
- 每次输出前自检是否符合契约，不符合则修正后再输出
```
> 来源：Musketeers Tech / Prompt Builder — 2026 Agent Prompt 实践
> 用法：把输出格式固定成"契约"，Agent 每次输出前自检，显著提升程序化调用场景的稳定性。

## 17. Hook-Shock-Validate-Tease 开场框架

**Prompt：**
```
Write an intro for this video that works as a hype man:
Video topic: [主题]
Key claim: [核心卖点/结论]

Framework (do NOT use these as headings in the output):
- Hook: strong, to the point, opens an information gap
- Shock: a surprising fact or counterintuitive statement
- Validate: why the viewer should trust/keep watching
- Tease: what's coming next

Rules:
- Extremely persuasive, conversational tone, like hyping up a friend
- Never start with "welcome" or "hi guys, welcome to the channel"
- Generate curiosity so they can't stop watching
```
> 来源：Reddit r/ChatGPTPromptGenius — ChatGPT Prompt to Write Brilliant YouTube Scripts
> 用法：Hook→Shock→Validate→Tease 四步开场框架，开场即制造信息缺口，让观众产生"必须看下去"的冲动。

## 28. 单代理 vs 多代理决策（3 信号）

**Prompt：**
```
Should I use a single agent or a multi-agent system for this task?

Task: [任务描述]
Current setup: [现有 Agent/工具]

Evaluate the 3 signals:
1. Does the task naturally split into specialized roles (research + writing + editing)?
2. Do sub-tasks need conflicting system prompts ("be terse" vs "be thorough")?
3. Should sub-tasks run in parallel for speed?

Recommendation logic:
- If all 3 are NO → single agent (multi-agent costs 3-8x, adds coordination overhead)
- If any is YES → sketch the multi-agent design with handoff protocol
```
> 来源：AI Builder Club — AI Agents in 2026: Build, Deploy, and Scale
> 用法：用三个信号判断是否值得上多代理，避免"听起来很酷就上"；多数场景单代理更省钱更可靠。

## 30. 工具调用契约与弃权规则

**Prompt：**
```
Write tool instructions for my agent. For each tool, define:

Tool: [工具名]
1. When to call it (triggers and conditions)
2. Required inputs (and how to get them)
3. Expected output shape
4. When to ABSTAIN (call nothing / ask for clarification)
5. What to do on error or timeout

Additional rules:
- Never guess input values — ask if missing
- Never over-call: if the answer is in context, don't fetch
```
