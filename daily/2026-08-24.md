## 1. 规则带理由的指令写法

**Prompt：**
```
请帮我完成以下任务：[任务描述]

规则如下（每条都附上原因，理解原因后你会执行得更准确）：
- 规则1：[规则]（原因：[为什么]）
- 规则2：[规则]（原因：[为什么]）

如果你认为某条规则与目标冲突，请指出来并说明理由。
```
> 来源：53AI — 2026 年真正好用的 30 个提示词技巧
> 用法：Claude 对「带理由的指令」理解得更好。别光列规则，解释为什么——模型能根据原因在边界情况下做出正确判断。

## 2. 上下文在前、问题在后

**Prompt：**
```
以下是与本任务相关的全部背景资料：
[文档 / 数据 / 上下文内容]

---

基于以上资料，请回答：
[问题]
```
> 来源：53AI / Anthropic 官方测试数据
> 用法：把文档、数据和上下文放在提示词前面，问题放最后。Anthropic 测试表明，问题放在上下文之后，回答质量可提升最多 30%。

## 3. 对话式写作循环（初稿→反馈→共改）

**Prompt：**
```
先给我一个初稿：[任务描述]

之后我会逐条给反馈，我们一起迭代修改。请记住：
1. 每轮只改我指出的部分，不要擅自重写其他内容
2. 收到反馈后先复述你的理解，确认无误再动手
3. 保持全篇风格一致
```
> 来源：53AI — 2026 提示词技巧（新手与高手的分水岭）
> 用法：从「一条完美提示词」转向「对话式迭代」。先出初稿再共同修改，比一次性要求完美输出质量高得多。

## 4. 提示词修订与逻辑冲突检查

**Prompt：**
```
请协助调整一份提示词。以下是我目前的版本以及我想修改的几个重点。
请先完整读完这份提示词，再根据我列出的调整事项，告诉我：
1. 哪些段落需要修改，建议怎么改
2. 整份提示词是否存在逻辑不一致、规则冲突或容易产生歧义的地方

我想调整的事项：
- [调整事项 1]
- [调整事项 2]

当前使用的提示词：
[粘贴你的 prompt]
```

## 5. HITL 人工检查点设计


## 6. 禁用词替换为决策标准（Agent 指令）

**Prompt：**
```
以下是客服 Agent 的指令改写任务：

原始指令：
"绝不要升级账单纠纷。除非绝对必要，否则避免升级。"

问题：带有 never / don't / 绝对 等强禁止词的指令会让模型畏手畏脚，甚至做出错误判断。

请改写为决策标准式指令：
1. 删除所有禁止类词汇
2. 用明确的「触发条件 → 动作」替代
3. 示例：当用户连续 2 次表达账单异议且情绪激动时 → 立即转接资深客服

输出改写后的指令，并说明每个决策标准的判定依据。
```
> 来源：Musketeers Tech — Prompt Engineering Best Practices for AI Agents (2026)
> 用法：现代模型对"禁止式指令"容易矫枉过正。把 never/don't 换成可判定的决策标准，Agent 行为更稳定可靠。

## 7. 系统提示词季度修剪与评估

**Prompt：**
```
对以下系统提示词做一次季度修剪审计：

[粘贴系统提示词]

检查：
1. 找出互相矛盾的规则（尤其是一次次事故后追加的补丁规则）
2. 找出已过时、不再需要的指令
3. 找出重复表达的段落
4. 评估总长度是否超出必要（目标：精简 30% 以上）
5. 给出精简后的完整版本，并列出每条删减的理由

注意：删除规则后，请指出哪些行为可能回归，需要重新评估。
```
> 来源：Musketeers Tech — Prompt Engineering Best Practices for AI Agents (2026)
> 用法：系统提示词会"越修越胖"——每起事故加一条规则，18 个月后变成 6000 token 的矛盾体。季度修剪+每次修剪后评估是标配。

## 8. 范例库沉淀（canonical prompts 内部工具化）

**Prompt：**
```
帮我建立一份"范例提示词库"：

我经常重复的任务：
1. [任务类型 A，附一个效果最好的提示词+输出样例]
2. [任务类型 B，附一个效果最好的提示词+输出样例]
3. [任务类型 C]

请：
1. 归纳每个任务的核心结构（角色/上下文/格式/约束）
2. 提取可复用的通用模板
3. 标注每个模板适用与不适用的场景
4. 指出范例中不一致的地方（不一致的范例会被模型平均化）
```
> 来源：Codeling — Master Prompt Engineering Best Practices for 2026
> 用法：把效果最好的提示词+输出存档成内部工具库。几个精悍的范例胜过一堆平庸的范例——这既是个人资产，也是团队资产。

## 9. 跨模型交叉评审循环（AI 审 AI）

**Prompt：**
```
第一步（模型 A）：
请完成：[任务]

第二步（模型 B 评审）：
请以挑剔的审核员身份审查上面这份输出，指出：
1. 事实与逻辑错误
2. 表达啰嗦或空洞的部分
3. 可量化的改进建议（要具体到怎么改）

第三步（回到模型 A）：
根据评审意见重写。重写后再次自检：是否还有同类问题？
```
> 来源：YouTube — 7 个超强 AI 提示词（2026 教程）
> 用法：让 ChatGPT 写、Gemini 审、再丢回 ChatGPT 改——两个 AI "吵架"往往能吵出最佳方案。适合重要文案、方案、代码。

## 11. 提示词 A/B 对照测试（Prompt AB Testing）

**Prompt：**
```
同一任务，请用两种不同写法各执行一遍，然后对比：

任务：[任务描述]

写法 A：
[提示词 A]

写法 B：
[提示词 B]

输出格式：
1. 两份结果并排展示
2. 从准确度、完整性、可用性三个维度评分（1-10）
3. 指出 A 胜出的点、B 胜出的点
4. 给出综合了双方优点的最终版提示词
```
> 来源：Promptitude — The Complete Guide to Prompt Engineering in 2026
> 用法：像做增长实验一样对待提示词：同一任务两个版本对照，用评分而非感觉决定留下哪个，迭代出最优写法。

## 14. 机会过滤器（YES/NO 快速决策）

**Prompt：**
```
帮我做一个简单的 YES/NO 过滤器，快速判断一个机会是否值得投入：

输出：5 个条件各给 1-10 分，总分低于 X 分直接拒绝，并给出拒绝话术。
```
> 来源：Chetan Pujari — 50 Claude Prompts Everyone Should Steal (2026)
> 用法：建立个人版"机会评分卡"，用 5 个硬条件对抗 FOMO，避免过度承诺——60 秒内决定接不接。

## 16. 大脑倾泻整理（Brain-Dump Clarifier）

```
2. 哪些可以明天再说
3. 每件事给出最小可行安排
```

## 23. 深度学习追问链（下一层问题生成器）

```

3. 对每个问题给出提示方向（不是答案，是思考线索）

```
> 来源：主动学习技巧（2026 深度学习提示词实践）
> 用法：把"学完就完"变成"学完追问"。连续 3-4 轮追问链能逼出教科书里没有的深层理解。
