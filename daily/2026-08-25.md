## 1. 含糊请求先问三个澄清问题

**Prompt：**
```
[你的请求]

如果我的请求含糊不清，请先向我提出最多 3 个澄清问题，再开始作答。问题要具体、直击关键缺口，不要泛泛地问"能多给点细节吗"。
```
> 来源：Reddit r/ChatGPTPromptGenius — 2026 Prompt Cheatsheet
> 用法：把"先问再做"固化成规则，避免 AI 凭猜测输出、浪费一轮对话。

## 2. 失败优先审视（Failure First）

**Prompt：**
```
在给出方案之前，先完成"失败审视"：
1. 列出这个方案在什么情况下会失败（至少 3 个具体场景）
2. 指出方案里最脆弱的一个假设
3. 说明哪些外部因素变化会让方案失效
4. 然后给出完整方案，并在方案中标注对应风险的缓解措施
```
> 来源：Reddit r/ChatGPTPromptGenius — 2026 Prompt Cheatsheet（failure first）
> 用法：先谈失败再谈成功，逼 AI 暴露方案边界，适合决策与规划类任务。

## 3. 输出黑名单：明确"不要什么"

**Prompt：**
```
请完成：[任务]

输出时明确禁止以下内容（黑名单）：
- 禁止使用这些套话/陈词滥调：[如 "in today's world"、赋能、闭环等]
- 禁止空泛形容词，每个结论必须给出具体依据
- 禁止与事实冲突的夸大表述

如果黑名单内容与任务要求冲突，请指出。
```
> 来源：53AI — 2026 提示词技巧（"不要什么"清单法）
> 用法：明确告诉 AI 不要什么，往往比只说要什么更有效——先给黑名单再给任务。

## 4. 零样本优先、范例后置

**Prompt：**
```
请分析输入数据并按要求产出：[任务 + 输出原则 1、2、3]

先不要给范例，直接按原则生成。如果输出格式不符合我的预期，我会再补充 1-2 个范例让你对齐。
```
> 来源：Data-DI — AI 提示詞技巧 2026（OpenAI 官方推理模型指南）
> 用法：2026 推理模型时代的新顺序：先 zero-shot，格式不对再补少量高一致性范例，避免范例框住模型。

## 5. 先列假设再解题

**Prompt：**
```
请先列出你对这个问题的所有关键假设（包括背景前提、数据假设、术语定义），确认我们理解一致后，再给出答案。

```
> 来源：Data-DI — AI 提示詞技巧 2026
> 用法：在提示词结尾要求 AI 先列假设，能在早期发现认知落差，阻断无效输出与幻觉。

## 6. 说目标不教步骤（适配推理模型）

**Prompt：**
```
请完成以下目标：[描述你想要的最终结果]

不要一步步拆解过程给我看，直接给出完成后的成果。只要结果符合要求即可，具体路径由你决定。
```
> 来源：Data-DI — AI 提示詞技巧 2026
> 用法：对 GPT-5.5、Gemini 3.1 Pro 等推理模型，跳过"请一步步拆解"类过程指令，让内部推理不被人工路径打断。

## 7. 推理力度与详细度参数设定

**Prompt：**
```
任务：[任务]

请按以下参数执行：
- reasoning_effort：[none / low / medium / high / xhigh]

选择理由：推理力度决定思考深度，详细度决定回答篇幅。默认 medium，复杂长链推理任务才用 high 以上。
```
> 来源：Data-DI — AI 提示詞技巧 2026 / OpenAI 官方参数指南
> 用法：2026 年提示词 = 文字技巧 + 参数设定双轨。把 reasoning_effort 和 verbosity 写进提示词，输出更稳定可控。

## 9. 链式提示：上一步输出作下一步输入

**Prompt：**
```
我们分步完成任务。每完成一步，我会说"继续"，你基于上一步的输出进行下一步：

第一步：[任务第一步]
第二步：[任务第二步，依赖第一步输出]
第三步：[最终输出，整合前两步]

每步输出前先复述你从上一步接收到的关键信息，确认没有丢失。
```
> 来源：数位时代 Business Next — 2026 最新提示詞 7 原則（链式提示）
> 用法：把复杂任务拆成链式步骤，前一步输出作为下一步输入，每步确认信息完整，减少长任务的信息丢失。

## 10. 自一致性采样：多次推理取共识

**Prompt：**
```
请对以下问题独立作答 3 次，每次不要参考前一次的回答：

问题：[问题]

然后：
1. 找出 3 次回答中的共识结论
2. 指出分歧点并分析原因
3. 给出最终答案并标注置信度
```
> 来源：k2view — Prompt Engineering Techniques: Top 6 for 2026
> 用法：自一致性采样：多次独立推理取共识，显著提升推理类任务准确率，适合数学与逻辑题。

## 11. 提示词自动化测试与回归（Prompt CI/CD）

**Prompt：**
```
我有一套生产环境使用的提示词。请帮我设计提示词测试方案：

提示词：[粘贴]
预期行为：[正常/边界/错误场景各 1-2 个]

输出：
1. 测试用例清单（输入→预期输出→通过标准）
2. 回归检查点：修改提示词后必须重新验证的行为
3. 需要监控的输出质量指标（如格式合规率、拒绝率）
```
> 来源：thomas-wiegold.com — Prompt Engineering Best Practices 2026（Promptfoo 思路）
> 用法：把提示词当代码对待：自动化测试 + 回归。生产环境提示词每次修改都跑一遍测试集，防止"修好 A 弄坏 B"。

## 30. 番茄钟工作流拆解

**Prompt：**
```
把这个任务拆成 3 个番茄钟（每个 25 分钟）：

任务：[任务描述]

输出：
1. 每个番茄钟的具体工作内容（边界清晰、互不重叠）
2. 每个番茄钟结束时的检查点（怎么确认这 25 分钟没白费）
```
