## 1. 验收规格式提示词（只写验收标准，不教步骤）

**Prompt：**
```
2026 推理模型提示法：不要替 AI 写完整的工作指令，而是替它写一份完整的"验收规格"。

请按以下格式交付任务：
任务：[描述最终要交付的成果]
完成 = 什么样子：[列出可检查的完成标准，如格式/长度/必须包含的要素]
背景：[谁要看、用来做什么、行业/上下文]
数据/资料：[AI 可以依据什么回答；没有资料就明说]
边界：[禁止事项、不要自行扩大的范围]
输出格式：[结构、顺序、篇幅]
验证方式：[如何自检，如"所有数字对照来源"]

只给目标与验收标准，中间步骤让模型自己规划。
```
> 来源：欸那個AJ — 2026 AI 提示詞最佳設計指南（GPT/Claude/Gemini 共通框架）
> 用法：把提示词从"流程说明书"改成"验收规格书"——推理模型自带规划能力，给足目标和验收标准输出更稳定，流程指令反而限缩其能力。

## 2. 五组件代码提示系统（角色-上下文-任务-约束-输出）

**Prompt：**
```
按以下五个组件组织代码类提示词，缺一不可：

1. 角色（Role）：Act as a senior [语言] [专项] engineer
2. 上下文（Context）：语言/框架/版本、代码用途、规模
3. 任务（Task）：具体审查/调试/重构类型，只聚焦一个维度
4. 约束（Constraints）：如"标注行号、按严重度排序、不改可观察行为"
5. 输出格式（Output format）：编号列表 / 表格 / 结构化报告

任务：[代码审查 / 根因分析 / 重构计划]
代码：[粘贴代码]
```
> 来源：Prompt Architects — 35 AI Prompts for Code Review, Debugging & Refactoring (2026)
> 用法：五件套缺一不可——少任何一件模型就用假设填补，产生与你的技术栈无关的泛泛而谈。

## 5. 分支式追问法（对 AI 输出的单点深入展开）

**Prompt：**
```

2. 请就这一点深入展开：[具体条目]
3. 给出 2-3 个替代方案，并与原方案对比优劣势
4. 说明你推荐哪一个及理由

当前输出：[粘贴 AI 上一次的回答]
```

> 用法：2026 年最佳实践是"迭代优于一次性"；AI 标出问题后立刻追问"展开第 3 点，生成三个替代重构，并和原逻辑基准对比"。

## 6. 角色设定取舍判断法（什么时候该写角色）

**Prompt：**
```
判断这个任务是否需要角色设定，并按结论输出：

任务：[描述任务]
判断标准：
1. 角色与任务是否直接相关？（"20 年经验的营销总监"如果不交代产品/市场/限制，就是空头衔）
2. 角色能否提供任务所需的专业术语和判断框架？
3. 背景设定会不会分散模型注意力？

结论要求：
- 需要角色：给出角色+一句话任务上下文+输出要求
- 不需要角色：直接给任务、资料和验收标准
```
> 来源：經理人月刊 / 数位时代 — 2026 Prompt 全攻略（角色设定的适用边界）
> 用法：2026 年角色设定仍可用，但"年资+头衔"已失效；角色必须与任务直接相关，否则背景描述越多越分散注意力。

## 7. 防过度思考与冗长输出抑制

**Prompt：**
```
处理以下任务时，注意控制输出篇幅与思考深度：

任务：[任务描述]
输出规则：
1. 直接给结论，不要先复述我的问题
2. 默认中等详细度；除非我要求"深入"，否则不要展开所有分支
3. 禁止输出"总结性段落"和"展望未来"式结尾
4. 如答案可一句话说清，就不要写三段
5. 不确定时才标注，不要用冗余措辞填充

若我的要求存在明显取舍（简洁 vs 全面），先问一句再回答。
```
> 来源：Claude Platform Docs — Prompting Best Practices（Overthinking and excessive thoroughness）
> 用法：Claude 类模型倾向过度思考与过度完整；显式给出"简洁规则+详细度开关"，可显著减少废话输出。

可用数据：[粘贴数据或描述数据范围]

分析流程：
1. 先把决策翻译成可回答的问题清单（每个问题对应数据里的哪个字段）
2. 数据质量检查：缺失、异常、口径不一致先说明
3. 按问题逐个分析，每个结论标注：数据支撑程度（强/中/弱）
4. 明确指出数据无法回答的问题（不要硬答）
5. 最终给出建议动作与截止时间

禁止：脱离决策堆砌图表、把相关性说成因果。
```
> 来源：Improvado — AI Marketing Prompts Guide: Best Practices 2026
> 用法：分析的目的不是"看数据"而是"做决策"；先写清决策再分析，输出才能直接用于行动。

## 61. 视频脚本分段产出与验收

**Prompt：**
```

## 62. 情绪天气日志

**Prompt：**
```
帮我建立情绪天气日志：

今天的情绪"天气"：[如 晴/多云/雷阵雨，用天气比喻描述今天的心情]
今天发生的事：[简要记录 2-3 件影响情绪的事]
身体状态：[睡眠/精力/饮食]

输出：

```
> 来源：基于 AI Academy / 身心健康提示词 2026 整理
> 用法：把情绪当天气记录——观察但不被它淹没；AI 帮你命名情绪、核对事实、给出小行动，长期积累可见模式。
